# Shared base

Rust domain and application crates depend only on inward interfaces. Native
SQLite and C ABI are separate adapters; the WASM binding excludes SQLite.

Current implementation includes lossless UTF-16 replica JSON, ECMA-compatible
canonical hashing, binary64 round-trip decoding, field externalization and
repository-backed use cases. Web/backend call the WASM core; native adapters
use SQLite, original-file/blob repositories and an independent HTTP service.
Network snapshots stage durably and finalize atomically without inventing
operations. Actual production HTTPS restore was verified on separate Windows
and Linux workspaces, including original files and reopen.

The Web business migration is incomplete. Native business commands still require
Unicode scalar strings even though the replica JSON model preserves lone UTF-16
surrogates. Direct JSON requests are capped at 16 MiB. Resource GC/quotas,
legacy workspace transition and production cutover remain open gates. See
[the current status](../docs/current-status.md).

## Build and verify

Install Rust 1.93.1 and `rustup target add wasm32-unknown-unknown`, then:

```sh
cargo test --manifest-path base/Cargo.toml --workspace --locked
cargo build --manifest-path base/Cargo.toml -p shufang-bindings
cd app
npm ci
npm run check
npm run lint
npm test
npm run build
```

The npm pre-scripts compile and embed WASM from this checkout. Generated bytes
are ignored. Do not use a prebuilt artifact from a different commit. Docker
builds its WASM in a Rust stage and embeds it in its Node stage; use repository
root as context: `docker build -f app/Dockerfile .`.

Native ABI 1 is documented in crates/bindings/include/shufang.h. Every allocation
and result must be freed. Requests/errors are versioned JSON; session handles
are opaque and process-local. `sessionClose` releases the SQLite connection.
Native requests include `sessionOpen`, `sessionClose`, `sessionNotes`,
`sessionSaveNote`, `sessionPending` and `sessionCommand`; the latter dispatches
native use cases, jobs and sync configuration. Core calls are synchronous;
invoke them off the UI thread. Long-running import/AI/backup tasks expose
job IDs, progress and cancellation. Buffers must never be accessed concurrently with execute/free.

See docs/native-core-migration.md at repository root for migration and recovery
requirements. SQLite 0003 is a separate native chain. MySQL remains 0014; the browser now
uses IndexedDB 11. Windows opens an explicit local workspace and can configure
native v2 peers; it does not silently adopt browser/MySQL files.

Linux/headless credential storage requires an independent 256-bit deployment
key in `SHUFANG_CREDENTIAL_KEY` (64 hex characters), or a peer's
`tokenEnvironment` reference. Windows retains DPAPI. An optional Linux service
owner token can come from `SHUFANG_SERVICE_TOKEN`; otherwise the encrypted vault
generates and retains it. Tests use an isolated public test key, as in CI. Never
reuse the test key for deployment. Local secrets and sync configuration are not
business operations or replicated to peers.
