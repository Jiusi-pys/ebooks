# 原生学习工作区与同步格式 v1

发布日期：2026-10-02。本文定义本机学习格式首次版本，以及现有 v2 同步中的可选字段。它不是 MySQL 迁移：本次不改变 MySQL 表、索引、约束或浏览器 IndexedDB 结构，不修改、重编号或删除历史 SQL 迁移。

## 版本与升级起点

支持从尚无原生学习工作区的旧 iOS 客户端直接升级。第一次打开账户时新建 `StudySnapshot.version = 1`；已存在的离线书籍、阅读历史和钥匙串会话保持原有格式。原生学习工作区不把旧 API key 缓存猜测为当前账户资料，也不要求用户逐版安装。

工作区位于 Application Support 下的 `Shufang/Study/<scope SHA-256>/`。scope 是规范化的服务器协议、主机、有效端口与账户 ID；同源默认端口及大小写归一，不同账户和服务器各自保存。`workspace.json` 包含副本 ID、时钟、服务器工作区 ID、增量游标、已同步实体、待发送操作与冲突；`attachments/<SHA-256>` 保存内容寻址的附件。密码、会话 Cookie、API key 和请求头不进入此格式。

每次修改先将新的实体变化与待同步操作一起原子写入 `workspace.json`，成功后才更新界面状态。重启、断网和登录到期均不会清空队列。无法解码或版本不是 1 时保留原文件、禁止覆写并提示恢复/更新；不把损坏文件当成空工作区。未来升级必须增加版本，并保留从 v1 顺序升级的读取和恢复步骤。

## 现有 v2 契约与可选扩展

卡片继续使用 `highlights` 实体和原 ID；脑图的 `sourceHighlightId` 引用它。学习集和脑图沿用 `studySets`、`mindMaps` 及现有成员/节点字段编码，不新增实体类型。

`highlights.sourceRanges` 是可选来源数组，支持跨段文字摘录。每个来源包含 `kind`、`bookId`、`chapterId`、`chapterTitle`、`text`，以及可选的 `paraIndex/start/end` 或 `pdfAnchor`。文字 start/end 是段内 UTF-16 半开区间；PDF 页码从 1 开始，矩形为旋转后的裁剪页左上角归一化坐标。原有主来源字段仍保留，旧客户端可继续使用第一个来源。

每页手写使用独立 `notes` 记录，ID 为 `pdfink.<SHA-256(bookID)>.<page>`。除现有标题、内容与时间字段外，增加可选 `bookId`、`pdfPage`、`pdfDrawing` 和 `pdfPreview`。后二者采用以下二进制引用：

```json
{"$attachment":{"sha256":"64 位小写十六进制","size":1234,"name":"drawing.pkdraw","type":"application/octet-stream"}}
```

`pdfDrawing` 是 PencilKit 原始笔画，预览使用 PNG。它们保持二进制，不使用会被旧版投影逻辑当作 JSON 解码的 `$blob`。原始 PDF 继续使用 `sources` 实体；大型 JSON 字段仍使用既有 `$blob` 协议。附件通过现有分块上传、逐块校验和最终 SHA-256 提交后，才发送引用它的操作。原文件保持不变，导出 PDF 写入新文件。

`GET /api/v2/capabilities` 添加可选对象：

```json
{"nativeStudy":{"version":1,"sourceRanges":true,"inkAttachments":true}}
```

顶层协议版本保持 2。旧客户端可忽略该对象；没有该对象的既有 v2 服务器仍可保存通用 JSON 字段及二进制文件。它不是客户端登录凭据，也不能替代真实账户认证。只有能力端点 404 才判断没有 v2；401、网络错误或 503 不降级为已支持。

新服务端的节点复制扫描同时识别 `sources`、`$blob` 和 `$attachment`。旧节点只认识前两种，因此可保留手写引用元数据，但不会主动复制手写文件；需要跨节点使用手写时，必须先升级参与文件复制的节点。未升级期间，原上传节点和 iOS 本机仍保有附件。

## 重试、冲突和混合版本

客户端先拉取服务器变更，随后逐条提交本机队列。已经发送的操作固定使用原操作 ID、时钟和内容重试；接收服务器增量中自己的操作后清除待提交项，因此丢失 HTTP 回执不会重复生成卡片或复习事件。更换工作区身份时暂停同步，不能把同一服务器地址下的新工作区与旧队列混合。

普通编辑只提交变化字段。原生类型化编辑保留其他客户端新增的未知字段；既有 v2 `validatePatch` 允许附加字段，服务端物化也不丢弃它们。兼容性以字段级 patch 为边界：旧客户端若显式删除一个字段或整条记录，其删除仍有效，不能视为“忽略未知字段”。本次新增自动测试验证旧式已知字段 patch 不抹掉 `sourceRanges`，并验证手写引用不会成为 JSON blob。

若队列触及的字段与保存时基线不同且不是自己的目标值，保留双方版本并暂停该实体的发送，允许保留本机、使用远端或另存副本。服务器删除使用墓碑，原 ID 不复活，需另存副本。未冲突的实体可以继续同步。书籍和原文件必须保留稳定身份，以免来源定位失效。

## 备份、失败恢复与发布顺序

1. 发布前备份服务器数据库及原文件/同步附件目录，记录镜像提交和现有迁移版本；迁移脚本历史归档不能替代这些数据备份。iOS 更新前可导出完整学习资料包，格式、校验和恢复策略见 [study-backup.md](study-backup.md)。
2. 先发布兼容现有 v2 的服务端能力声明和附件复制支持，再更新 iOS；既有网页和原生客户端无需同时升级。本次没有 SQL 或 IndexedDB schema 变更，不能运行生产 `db:push`，不新增空迁移来伪造数据库升级。
3. 新版 iOS 第一次打开账户只建立 v1 本机文件；重复启动使用同一工作区、队列和副本身份。完成离线修改、重启、重新登录和真实 v2 回执验证后，再做多节点附件验证。
4. 本机文件写入失败时保留旧状态并显示错误；网络失败保留队列供重试。损坏或更新版本的工作区先保留整目录独立副本，再在兼容客户端从已校验备份恢复，不删除原文件“重置”故障。完整包恢复先校验和预览，再执行本机事务。
5. 程序回滚不会撤销已经同步的资料。旧版 iOS 不读取新工作区目录；降级期间不要移除目录或附件，重新升级可继续恢复。旧服务端暂时不能复制新增手写附件，恢复新版本后重试；若需灾难恢复，按部署文档一起恢复数据库与原文件/附件备份，而非仅切换容器。

## 验证记录与限制

原生测试覆盖离线重启、账户/服务器隔离、未知字段保留、复习与事件原子保存、来源定位以及备份校验。2026-10-02 的服务端定向验证：能力成功/401/503、可选字段保留、二进制手写双向传输、附件缺失后重试，以及既有 blob/同步回归，共 5 个文件、23 项测试通过。测试采用与仓库逐文件 SHA-256 一致的本机副本和 lockfile 指定、完整性校验后的最小依赖集合；见 [测试日志](evidence/native-study-server-20261002.log) 和 [源码/依赖清单](evidence/native-study-server-20261002.json)。

完整 `check`、`lint`、`test`、`build` 曾因原目录 iCloud dataless 依赖读超时及磁盘不足而未完成；定向测试不替代这些完整检查，也不代表真实 MySQL 或生产多节点验收。原生与真机执行结果统一记录于 [verification.md](verification.md)。

当前实现是新增本机格式 v1，不存在更旧版本的学习工作区升级链；未知版本拒绝读取已纳入验证。此次未改变数据库结构，空库、上一版本和跳版本 MySQL/IndexedDB 迁移测试不适用于此补丁，不能把它们记为已运行或已通过。真实多节点、低存储、云盘中断、长 PDF、Apple Pencil 及真机覆盖范围须以本次实际记录为准。
