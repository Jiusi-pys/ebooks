# IndexedDB 11：首次提交前字段外置与快照暂存

起点：现有 10，以及仍支持的旧 8/9（保留原有 presence repair，顺序补齐）。
升级不删除或回填历史 outbox、实体、文件和业务记录。在现有 syncMeta 中记录
`field-outbox-format-v1`；`field:<sha256>` 保存 version=1、manifest 和 ArrayBuffer。
新记录大于 128 KiB 的 JSON 字段在生成 operation ID 前外置；字段对象、业务行、
实体状态及 outbox 在同一事务提交。SHA-256 分块同步计算，不等待网络或 WebCrypto，
避免 IndexedDB 事务提前结束。256 KiB 单块，最大 256 MiB 对象。

历史 outbox 保留原 ID 和内容。发送器不可改写大字段、workspace 或时钟；无法发送的
历史大操作进入显式导出/迁移流程，不能悄悄改成同 ID 的另一份内容。

旧标签页收到 versionchange 后关闭，重新打开旧代码因版本较低失败，必须刷新。
服务器 v2 标准 JSON 和 blob 格式不变；不能同时运行旧写入者。生产切换前导出业务、
原操作日志及原文件，并验证全量恢复。迁移源码备份不替代真实书库备份。

失败：升级事务回滚；写入失败回滚业务、对象及 outbox。保留原导出，恢复到独立
浏览器配置/书库并核对记录及文件 SHA，不通过降低版本清空用户数据。

验收：空库、10->11、8/9->11、重复打开、升级失败恢复、旧 outbox 和记录保留、
大字段首次提交外置、事务中断无半条记录、发送重试内容不变。快照暂存只写 syncMeta，
完整收齐后单事务合并业务投影与实体，保留本地 outbox，并推进同步水位。

0010-*.source 是更改前的 10 版源码备份。新增发布归档应同时携带全部 MySQL/SQLite
迁移、IndexedDB 历史源码和本升级说明，并提供 SHA-256 清单；历史归档不可覆盖。
