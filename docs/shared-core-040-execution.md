## 无损 JSON 设计及兼容步骤（实现前）

核心 JSON 字符串和键保存 UTF-16 码元，数字为 JavaScript IEEE-754 binary64；规范化 JSON 按 UTF-16 键序和 ECMAScript 数字格式输出。传输/存储仍是标准 JSON，孤立代理项用 \uXXXX 转义，不增加占位符或标签对象。此表示保持旧 MySQL 0014、SQLite 0003、IndexedDB 10 的 JSON 字段格式，不新增 DDL，不重写历史操作、迁移校验或既有数据库账本。

适用起点为现有旧 Web v2 JSON 记录及 SQLite 0001–0003 支持链；先通过新旧解析/规范化和业务差分，备份原数据库/日志/文件，再在隔离副本上读取全部记录，最后启用新读取器和单写入路径。不得通过替换字符、重写 operation ID 或丢弃难以解析的数据完成升级。旧节点能读取新写入的标准 JSON；不能处理的业务版本受切换写入栅栏限制。

失败保留原数据与备份，停止新写入。恢复到独立目录并核验逻辑记录和原文件，不能以程序回退替代数据恢复。后续若需要 MySQL/SQLite/IndexedDB 新结构，必须另先设计追加迁移、独立全链归档及空库/跳版本/重复/失败恢复验证。

### 入站快照暂存格式（实现前）

SQLite 0003 的 `local_values` 新增独立命名空间 `sync:incoming:<peer>` 和 `sync:incoming-page:<SHA256(peer + NUL + snapshot)>:<page>`，值为 version=1 的元数据及标准 JSON 状态文本数组；不改变 SQL schema 或历史迁移。哈希命名避免不同 peer 使用相同快照 ID 时覆盖彼此，也限制内部键长度。旧版本不会解释此命名空间，不得同时启动旧写入者。起点仍为 0001–0003 全链升级，生产启用前独立备份数据库、操作日志和原文件；异常可保留暂存并重启续传，废弃后重新拉取完整快照，不能提前推进水位。

页暂存事务核对快照身份、页序及续传标记；全部页确认结束后，在单个事务内与当时最新本地状态合并、保留永久删除及本地较新字段，推进 HLC 和已确认水位，再清理暂存。快照不生成或重写原始 operation ID；同字段版本不同内容须报冲突，不能靠接收顺序掩盖。失败回滚状态、水位和暂存清理；验证包括中断重启、页重复/乱序、损坏输入、最终水位 CAS 失败和本地待发操作保留。此为内部适配器格式设计，尚不代表网络恢复工作流已接入。
