## SQLite 0003 迁移设计（先于代码）

支持空库、0001、0002 一次顺序升级。保留 0001/0002 原文件及校验账本；0003 只新增同步快照表和索引、持久化日志世代。现有 outbox 保留全部操作并作为按提交顺序的复制日志；接收操作也记录于该日志，原有 ID/顺序不改变。重复 ID 必须先比较原操作内容；相同内容幂等，不同内容拒绝。发送确认、接收游标和上传进度使用已有 local_values，接收游标与实体操作在同一 SQLite IMMEDIATE 事务提交。网络调用在事务之外。

迁移 DDL、初始化世代、迁移回执和 user_version 在同一事务；错误全部回滚，可修复外部冲突后重试。未知版本和历史校验漂移拒绝打开。较早程序不能打开 0003，升级先关闭旧写入者。新 Web/MySQL 仍遵守 v2，不删除旧字段/API。

升级前用受维护锁保护的在线 SQLite 快照备份数据库、原文件、加密凭据并校验。失败保留旧库；恢复到新目录、关闭所有写入者后使用对应程序。程序回退不撤销 schema。备份凭据受 Windows 用户/机器 DPAPI 限制。

添加 0003 时追加 app/db/migration-history 完整历史归档及 SHA-256 清单，标注 HEAD 和工作区来源，不覆盖任何旧归档。验证空库、0002→0003、0001→0003、重复、失败恢复、原记录/outbox 保留及未知版本。

## Linux 凭据适配器设计（实现前）

Linux 无交互桌面密钥环时，服务使用部署环境提供的 `SHUFANG_CREDENTIAL_KEY`（64 位十六进制、256 位密钥），通过 ring AES-256-GCM、每次随机 96 位 nonce 加密节点本地凭据。密钥不写入工作区、同步日志、备份或输出；密钥需在部署密钥系统独立保管，恢复时重新注入。Windows DPAPI 原格式不变。Linux 此前拒绝文件凭据存储，无已发布可读旧格式；新格式带固定标识，错误密钥/篡改/未知格式拒绝读取，缺少密钥拒绝写入。Linux 凭据目录/文件权限 0700/0600，不回退明文。外部 `tokenEnvironment` 引用也可使用，无需复制密钥。

该变更不修改数据库或 IndexedDB。切换顺序为备份数据库及文件、保存独立密钥、配置新服务环境、运行隔离 round-trip/篡改/错误密钥验证后启用。失败关闭服务并保留原文件；恢复到新目录且使用对应密钥。隔离 Linux 测试使用公开测试密钥，不用于部署。
