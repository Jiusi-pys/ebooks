# 汉王尺寸模拟方案

本轮使用 MuMu 1 号实例及独立验收包 `org.shufang.android.acceptance`。正式包和用户书库保留。执行器为 `platforms/android/scripts/test-hanvon-mumu.ps1`，仅修改指定实例，结束后恢复原分辨率、密度及字号。

## 型号与资料

| 型号 | 屏幕 | 竖屏像素 | 物理 PPI | 机身尺寸（评测资料） | 推算有效显示区域 |
|---|---|---|---|---|---|
| N10 Pro 二代 | 10.3 英寸 | 1860×2480 | 300 | 226.6×201.6×5.5 mm | 157.48×209.97 mm |
| Clear7 原版 | 7.0 英寸 | 1264×1680 | 300 | 155.7×135.8×3.9 mm（评测标注，未核验最厚握持部位） | 107.02×142.24 mm |

N10 Pro 二代不是 10.9 英寸，也不能混用初代 N10 Pro 参数。Clear7 本轮指原版，不包含 Clear7C、Turbo、Ultra 或 7.1 英寸锦鲤款。有效显示区域按像素÷300×25.4 推算，受标称 PPI 舍入影响，不是卡尺实测；机身尺寸不是 Android 布局输入。

资料依据：

- [N10 Pro 二代发布参数（IT之家）](https://www.ithome.com/0/842/106.htm)：10.3 英寸、2480×1860、300 PPI、Android 14。
- [N10 Pro 二代第一手评测参数](https://zhuanlan.zhihu.com/p/1890129867695170989)：机身 226.6×201.6×5.5 mm，屏幕参数交叉核对。
- [Clear7 原版第一手评测](https://post.smzdm.com/p/arr2gqng/)：7 英寸、1680×1264、300 PPI、机身尺寸。
- [Clear7 屏幕参数独立交叉核对](https://post.smzdm.com/p/apmlk427/)。

原版官方完整规格表及两机出厂 `densityDpi` 未取得，机身数据按评测资料标记。不能把物理 300 PPI 当作已核验的出厂逻辑密度。

## 可复现的模拟范围

MuMu 自定义参数使用横屏顺序 width=长边、height=短边，重启后实际 `wm size` 必须为上述竖屏像素。主配置采用逻辑密度 300，另补测 240、320；记录实际 Compose 配置、字体缩放及截图，不以计算值代替运行记录。

| 配置 | Clear7 理论宽度 | N10 Pro 二代理论宽度 |
|---|---|---|
| 300 dpi / 竖屏 | 674 dp | 992 dp |
| 300 dpi / 横屏 | 896 dp | 1323 dp |
| 240 dpi / 竖屏 | 843 dp | 1240 dp |
| 320 dpi / 竖屏 | 632 dp | 930 dp |

系统边距和取整会影响实际可用高度。300 dpi 横竖屏分别执行字号 1.0、1.3、2.0；240/320 dpi 补测竖屏字号 1.0。每个配置真实操作书架、搜索、打开正文、阅读工具、返回，以及双 PDF 选择、独立位置、手势同步滚动、结束对照位置保留。每机额外跑全套设备验收，覆盖备份、原文件移除、离线冲突及学习业务。

MuMu 的 Android 15、x86_64、GPU、普通 LCD 模拟环境不能复现汉王系统、ARM 性能、电磁笔、灰阶残影及刷新。尤其 N10 Pro 二代为减屏层笔操作设备，模拟器手势只能证明软件事件与布局，不能证明实体笔的点击、压力及按键映射。真机接入后仍需核验实际逻辑密度、笔、物理按键、厂商刷新和性能。

## 执行

先按 `test-device.ps1` 构建并安装独立验收包与测试包，再执行：

```powershell
./platforms/android/scripts/test-hanvon-mumu.ps1
```

执行器需要已构建的 Rust 隔离服务 `base/target/debug/examples/android_fixture_server.exe`，复制到新临时目录运行，不使用线上账号。完整原始结果位于 `docs/evidence/android-ios/runtime/hanvon-mumu-final/`。`results.json` 表示逐项运行结果；全套日志的条件跳过须单独统计，不能记为实际通过。控制器等待实例退出、重连失效的 ADB 连接，并在 MuMu 忽略过早的启动请求时重新启动。
