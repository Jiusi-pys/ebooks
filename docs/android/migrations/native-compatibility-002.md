# 原生兼容格式 002：学习资料传输与合并

基线 android HEAD 40f84d9，已有未提交兼容扩展 001；iOS 201a87a / 1.4.2 build10。无数据库 schema 变更，不修改任何历史迁移。

先扩展接口，继续保留 ABI 1、实体身份与现有字段版本。新增资料包沿用 ShufangStudyBackup v1，ZIP 是传输封装；清单和全部 payload 在独立暂存目录内验证，路径、大小、重复项、SHA-256、附件依赖、书籍章节均在写业务库前校验。

恢复预览固定资料包哈希、目标工作区身份和当前业务时钟；用户选择保留本机、双方副本或备份版本后，再备份原工作区并提交。引用按实体类型映射，手写 ID 随映射后的 bookId 重建，复习事件随对应卡片映射。提交前时钟变化拒绝原计划，重新预览；提交失败保留原库与原文件。原文件及附件先内容寻址暂存，业务事务失败仅留下可回收文件，不允许出现已引用但缺失的附件。

首次合并计划增加 mappingVersion=2，复制所有 $attachment/$blob 引用，手写笔记保持 pdfink.<SHA256(mappedBookId)>.<page>。旧计划保持原映射与已完成 receipt，不静默改写。含手写的旧计划若尚未提交对应笔记，可采用新手写身份；已提交的旧手写计划明确拒绝升级，保留原库和暂存库，须重新建立干净暂存工作区后确认合并。

新增计划同时收集不可变的 reviews 历史事件：只重建目标卡片引用与目标事件身份，保留评分、调度状态、createdAt 和 deviceId，不重新评分。Swift 数字日期可包含小数毫秒，必须原样保留；评分和复习次数只允许整数。旧版计划未收集复习事件，当原库包含历史事件时拒绝继续，要求重新预览干净暂存工作区，不能将遗漏历史的导入报告为完整成功。通用 save 仍不能写 reviews；历史事件导入拒绝覆写既有身份。此扩展不新增数据表或迁移。

历史输入归档位于 compatibility-history/002-study-transfer，附 SHA-256。该归档不等于用户数据备份。程序回退保留新增可选字段及资料包，不撤销已提交操作；恢复原工作区使用提交前整库和文件备份。未知资料包或计划版本拒绝写入。跨端双向资料包、冲突策略、篡改、缺失附件、路径穿越、迟到提交与故障注入测试通过前不标记完整恢复验收。

ZIP 封装由 Android 和 iOS 输出 stored entries；iOS 校验中央目录与本地头一致、CRC、路径、重复项、完整清单及 SHA-256，拒绝加密、符号链接、ZIP64 和压缩封装。保留原目录包入口。PDF 卡片缺省的章节标识/标题在 iOS 解码为空字符串，不改变 UTF-16 或页坐标；可选 sourceRanges 的 null 与缺省等价，错误类型及空数组仍拒绝。恢复验证覆盖这种物化记录，业务事务规则不变。这些是 v1 的读取兼容扩展，不修改数据库 schema、字段版本或历史操作身份。
