## 503 与真实服务器

后续更新（2026-10-08）：已复现认证同步快照 503，确认 MySQL 专用写连接失效后未重连，永久服务端热修复已部署并实际验证。详见[503 根因、测试与线上验收](../evidence/sync503-review.md)。以下段落保留前一次 UI 验收当时的调查范围。

目标为 `https://us.jiusi.org`。本次公开 HTTPS 检查 `/api/auth/session` 返回 200，`configured=true`；匿名 `/api/v2/capabilities` 返回 401。这是预期认证边界，不能视为账号登录或同步成功。`/health` 在公网返回 SPA HTML，不能据其 200 推断 Rust 后端健康。

另一个用户任务“修复 US 书库 503”报告已清理缓存，可用空间从 37 MB 增至 942 MB；认证后的书库连续三次 200，9 本书可读，抽查原文件 200。该任务未复现原始 503，故不能宣称确认根因。本 Android 任务没有并行修改生产服务器。

客户端增加结构化 HTTP 错误处理：HTML 503 保留 HTTP 状态，不输出服务端 HTML；账户存储不可用明确提示服务器数据库/磁盘检查；401 提示本地修改保留；200 HTML 明确拒绝为非 JSON API。4 个新增 JVM 用例先失败后通过。此改动不把服务器错误伪装成成功。
