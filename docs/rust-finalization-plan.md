# 后端剩余验收计划

范围：保持 MySQL 和既有前端；完成完整源码镜像构建、真实部署监督器发布/回退门槛，并交付外部账号人工授权步骤。

1. 在独立本机 Linux 构建器验证 Dockerfile.rust 全链，避免 1GB 生产主机的磁盘/内存约束。
2. 若生产主机无法源构建，追加明确的预构建发布模式：只接受管理员本地登记且提交标签、不可变镜像 ID 均匹配的 Rust 镜像，HTTP 仍仅接受完整提交 SHA。先失败测试，再实现；保留默认源码构建模式，验证备份/迁移先于停写和健康检查回退。
3. 使用真实 MySQL/HTTPS 监督器完成兼容 Rust 升级，保留原静态文件与写入者锁。发布失败不回退数据库，恢复使用同一数据/原文件目录。
4. 读取实际服务 Codex 状态及外部配置可用性；无有效用户授权时不伪造登录或把无凭证报错算真实模型成功。
5. 文档给出 Windows SSH/设备授权、浏览器 AI 全功能及 MCP 客户端验收步骤和通过标准，用户不必手动重复已完成的破坏性整库测试。

新增部署模式不变更数据库结构，无新增迁移。任何检查失败先修复再发布。计划沿用用户已授权的后端修复、部署及 base 提交范围。
