# MCP 升级与服务验收计划（2026-10-05）

范围：`base` 服务端 Node/MySQL 与 Rust/SQLite；不改前端或客户端界面。Node 仍为生产过渡服务，Rust 按现有路线逐步承接。当前工作树已有未提交的后端修复，作为同一候选版本验收。

## 实施顺序和门槛

1. 先以失败测试固定 2026-07-28 `server/discover`、无会话请求和工具调用；再迁移 TypeScript SDK v2。保留 2025-11-25 客户端连接和现有 OAuth/API key。Rust HTTP/stdio 提供同样的双版本入口与六项只读工具契约。对非法 Origin、协议头和工具名做负例。
2. 本地运行 Node 类型、lint、全测试、构建，Rust fmt、workspace 测试、Clippy，迁移与部署监护检查。只使用隔离数据库验证 MySQL 升级/重复运行/失败恢复；不改已发布迁移。
3. 远端只读盘点服务、镜像、磁盘和现有备份。必须先获得足够的独立空间；保留现有运行镜像和至少一份可恢复旧版本。部署前停写取得同一时间点的 MySQL、原文件、运行配置及密钥备份，校验哈希，并在隔离位置恢复预演。
4. 候选镜像精确关联本地源码哈希。先用隔离 MySQL、独立运行目录、独立端口验证 HTTPS、OAuth/MCP 双版本、同步及跨节点恢复；记录实际请求/响应、操作数和原文件哈希。生产单写入者切换时停止旧写入者，确认只有目标实例可写，失败则保持旧实例停写并从独立备份恢复；程序回退不视作数据库回退。
5. 只有上述全部通过且监护观察无回归，才把精确候选代码提交至 `base`，并核对远端部署 SHA 与本地提交一致。任何门槛失败，保留生产现状、记录阻塞和证据，不提交 `base`。

## 已知前置风险

2026-10-05 远端根分区预检仅余约 186 MiB。此时不能安全构建镜像或完成双份数据备份；空间处理前不得部署或切换。旧版 Node WebHook 尚无持久投递；本轮不把进程内分发宣称为可靠队列。Rust 目前没有取代全部 Node/MySQL 生产业务，因此生产 Web 写入者仍应为 Node，Rust 作为隔离跨节点验证端。
