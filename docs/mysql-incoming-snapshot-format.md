# MySQL 入站快照暂存格式 v1（实现前设计）

起点为完整 MySQL 0000–0014 迁移链；不改变 DDL、既有迁移及操作内容。
复用 `sync_snapshots` / `sync_snapshot_entities`，本地暂存 ID 为
`incoming:<SHA256(workspace + peer checkpoint key)>`。checkpoint 保存 v1
元数据、远端快照 ID、水位、续传位置、页数及开始时接收游标；状态保存标准 JSON。
`sync_cursors` 的 epoch 专属接收键及独立快照时间键记录恢复结果。

执行顺序：备份数据库、原文件、配置；隔离恢复；发布完整迁移链并停旧写入者；
分页只暂存，核对身份、页序及续传位置；最终单事务锁住 workspace head、校验
游标 CAS，以 application WASM 合并全部状态、更新 HLC、水位与完成时间，然后清理
暂存。不插入或改写原操作；正常 changes 单独保留仍可获取的原日志。
混合版本 v2 JSON/blob 协议不变，旧服务不能作为此暂存格式的并发写入者。

中断后从持久化位置继续；远端过期仅废弃该下载；最终失败回滚实体、HLC、游标和
暂存删除。程序回退不撤销数据格式：保持旧写入者关闭，必要时从备份恢复到独立
目录及数据库并核对状态/原操作/文件，再切换。暂存不作为独立备份。

验证门槛：空库完整初始化，0014 库保持迁移链与原数据，页中断/重启、重复旧响应
拒绝、最终版本碰撞回滚、游标 CAS、待发原操作保留及重试恢复。生产切换另需实际
HTTPS、原文件恢复、本地增量核对和单写入者验证。

浏览器暂存使用 IndexedDB 11 已有 syncMeta，不新增对象仓库。开始下载时保存
expectedCursor（缺少游标为 null），最终事务比较当前接收游标后才合并。此前没有
该字段的未完成下载不能安全完成，应废弃并重新下载；原实体、待发记录和游标
不受影响。升级不改写已发布的 IndexedDB 升级分支或历史源码归档。
