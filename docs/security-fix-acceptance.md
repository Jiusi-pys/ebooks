- 四个原始触发场景先失败，修复后通过：极端同步时钟不能污染 head；已撤销 OAuth 令牌不能随整库恢复复活；匿名注册不能占满客户端额度；受信代理后的不同客户端独立限流。
- 同步普通/lossless 接收、显式本地时钟、快照暂存和旧暂存快照发布均有时钟边界检查；计数器满位能够单调进位。正常同步、历史离线时钟、正常写入及重开继续通过。
- OAuth PKCE、授权页 CSRF、一次性消费、令牌刷新轮换、撤销与旧客户端兼容通过；250 次匿名注册及 150 次匿名授权页请求不持久占用全局额度。
- Windows 和 Linux：`cargo test --locked --offline --workspace`、`cargo clippy --locked --offline --workspace --all-targets -- -D warnings` 通过；Rust 格式及 diff 检查通过。独立复核未发现新的可确认问题，并独立通过 11 项认证/安全回归测试。
- 兼容旧 Node 工程的 `npm run check`、`npm run lint`、`npm test`、`npm run build` 通过（611 项测试通过、53 项按原配置跳过）；部署监督器 15 项测试通过。构建产物不提交、不替换生产前端。
- 生产主机的真实 MySQL 8.4 使用两个全新隔离库各执行完整 16 个迁移，4 个 MySQL repository 测试通过。验证恢复保留实体和操作日志、改变同步 epoch、移除旧接收游标、保留客户端注册并清空五类 OAuth grant 状态、拒绝并发第二写入者、关闭后交接新写入者并继续写入。测试库已删除，未在生产书库执行破坏性恢复。

## 生产代理门槛

现场链路为 sing-box Trojan TCP/TLS 443 → Nginx 127.0.0.1:8080 → Rust 127.0.0.1:31432。当前 fallback 转发没有传递真实客户端 IP；Nginx 所见 remote_addr 是回环地址。仅配置 `proxy_set_header X-Real-IP $remote_addr` 无法消除跨客户端登录限流串扰。

Rust 只信任真实 loopback socket 上、由受信代理覆盖的单值 X-Real-IP；不信任缺失 ConnectInfo、远端直连的转发头、逗号列表或重复头。代理必须从可信的连接身份获得 IP 并覆盖传给 Rust 的头，禁止直接透传用户输入。共用 TLS 入口调整还涉及非书库服务，须单独取得用户范围授权，再以备用端口验证 HTTP/Trojan 两条路径、生产切换及回退。此门槛完成前不得宣称生产登录限流已完整验收。

## 恢复与用户确认流程

- 整库恢复会撤销所有现有 OAuth 访问/刷新令牌及待处理授权码/授权请求，需在连接器中重新授权；普通重启、升级和单实体版本恢复不撤销授权。
- 已被旧版本污染的历史 head 不会自动重写；应选择健康版本恢复。版本快照仍可手动选择删除，不自动清理用户快照。
- 发布后在浏览器登录书库，刷新并打开一本测试书，确认初始化不出现 401。
- ChatGPT 连接器完成书库 OAuth：先登录书库，再从连接器发起授权，在授权页同意并返回 ChatGPT，调用书目工具；随后在连接器撤销授权，旧令牌应不可继续使用。授权过程不要发送令牌或验证码给他人。

MCP 可读取原文及提供完整用户操作能力是产品意图，不再列为越权发现。本补丁不削减原文权限，也不把现有六个只读工具宣称为已实现全部写入能力。
