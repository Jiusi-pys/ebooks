# Rust 安全修复方案

基线 base 8d9a65f，修复四项经隔离复现的问题。保留 MySQL、现有协议及版本快照手动删除，限后端范围。

1. 同步操作、显式本地时钟、lossless 操作和快照字段在提交前拒绝超过本机一天的未来时钟；十位计数器用 wall+1/counter=0 进位。旧版本已暂存的快照在发布事务中再次校验，失败不更新实体、日志或 checkpoint。历史离线记录可接受；异常未来节点须先校时。已有被污染的历史 head 不静默重写，须从健康版本恢复。
2. SQLite 和 MySQL 的整库恢复事务保留已注册客户端，清空 OAuth pending/codes/access/refresh/used_refresh，涵盖历史 hex 和现行 base64url token hash。保留已初始化的 oauth-store 防止旧 Node 授权导入复活。单实体恢复不重置授权；普通重启不撤销授权。无 DDL、迁移版本或已发布迁移变更。
3. 公开 OAuth 注册和授权页采用用途分离的 HMAC 签名封装，匿名请求不持久占用全局额度；注册有效期一天、授权页十分钟，元数据和封装有大小上限。成功同意才持久化客户端和一次性消费标记。保留旧 client_id 与未过期旧授权页兼容，现有授权继续有效；PKCE、CSRF、账户凭据版本和刷新轮换检查保持执行。
4. 登录按真实连接身份限流。只有真实 loopback ConnectInfo 可读取 Nginx 覆盖的单值 X-Real-IP；缺失、重复、非法和直接远端伪造头均不获信任，IPv4 映射 IPv6 归一化。生产代理必须覆盖该头，服务监听回环。

TDD 顺序：四个原始触发测试先失败；修复后验证攻击类与正常路径、旧暂存快照、代理伪造头；工作区测试和 Clippy；独立补丁复核；隔离真实 MySQL 恢复和单写入者验收；Linux 构建、备份、监督器发布与 HTTPS 验证；提交 base。

MCP 产品意图按用户声明为完整书库操作能力，包括原文、导入、元数据和封面。撤回此前把读取原文判为越权的发现。本次四项补丁不削减原文读取。当前六项工具与 library:read 授权仍属已实现的只读子集，完整写入工具及对应授权声明属于后续能力扩展，不能宣称已由本次安全补丁实现。
